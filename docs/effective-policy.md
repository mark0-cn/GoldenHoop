# Effective policy and finite lease readback

The Rust manager and Docker driver have an explicit effective-policy readback path. It validates the complete actual inet policy and a finite kernel lease alongside the original source, DNS, Ethernet and destination binding. The driver retains a process-local lease while its caller holds the controller session. This component does not itself publish Ready. The separate [worker-held session path](worker-network-policy.md) adds durable desired policy and live dispatch gating; its supported-host acceptance remains a separate gate. Public provisioning, credentials and the remaining M3-M6 work remain required; NetworkPolicy and SecretInjection remain unadvertised.

`policy_readback::verify_structure` reconstructs the expected policy from the full `Config`, allocation, revision, exact DNS listener tuples and active DNS set generation. It checks every table, chain, hook, priority, ordered rule expression, set declaration and named-set reference. The comparison includes layered user policies, administrator allow/deny overlays, TCP port caps, default verdicts, IPv4/IPv6 address targets and prefixes, DNS input restrictions and redirection. Unknown native objects, extra permissions, foreign set references, dormant tables, permanent members and changed revision/owner chains refuse.

The parser normalizes checked representation differences from actual nft output: interface names for a frozen index, numeric protocol/ICMP forms, singleton anonymous sets and omitted redundant TCP protocol dependencies. Counter values and native handles are metadata. These normalizations do not authorize a different interface, protocol, target, verdict or evaluation order. Actual captures and altered observations test this boundary. A table hash or revision marker alone is insufficient.

The live set must contain only the original bridge with a finite timeout. JSON output truncates duration precision, so native text supplies the millisecond remaining time. The manager brackets that read with monotonic timestamps, computes a conservative lower bound and refuses a lease that expired during observation or exceeds the original lifetime. It checks the policy structure again after the native read. The existing DNS duration parser and conservative timer/display margins also apply here.

The manager retains the exact configuration only in its current process. Installation verifies the complete resulting rules and live element before it permits renewal. Renewal fences its state before readback, verifies the existing policy and actual live lease before any refresh, then verifies the result again. An expired kernel element cannot be recreated by supplying its old revision. A cold controller has no effective-policy authority: recovery still requires owned quarantine and fresh configuration.

For native-bound DNS, live element durations are capped against the original monotonic sandbox deadline with room for installation/readback. The original absolute expiry remains unchanged. Failure, timeout or uncertain observation cannot produce a new effective receipt. These readbacks establish the observed finite bound; workload lifetime enforcement and reconciliation remain the worker's responsibility.

Active DNS set inspection compares every observed address and authority with the original source book and its absolute expiry. A periodic inspection may observe a conservative subset after early kernel expiry, including a member already expiring during the sample; it creates no new source credit and publishes no DNS answer. The new-grant handshake still requires every requested member to have a positive confirmed lifetime before returning an answer. DNS set activation now rechecks the complete effective policy and global lease before it clears uncertainty.

`InspectPolicy` requires the original native context, an actually running DNS frontend, all immutable floors, the matching effective configuration and a known live lease. It returns `EffectivePolicyReceipt`: the protected binding, configuration fingerprint, native snapshot fingerprint and positive bounded remaining milliseconds. Collection-only processes reject this operation. Frontend/context checks run before and after the exchange. The native fingerprint is trace evidence; exact semantic and expiry readbacks supply the proof.

The Docker driver offers `apply_protected_policy`, `replace_protected_policy` and `renew_protected_policy`. Initial activation first inspects complete quarantine. Replacement and renewal inspect the current effective policy. The driver matches the frozen controller/native plan and both Docker endpoint views, requires fresh full receipts before and after endpoint observation, and preserves source/DNS/destination identity and original expiry. A duplicate initial activation refuses before mutation. Once mutation begins, cancellation or any unconfirmed result fences the session.

`VerifiedPolicyLease` has private fields and a monotonic deadline. It is not serializable into restart authority. The driver anchors the returned duration at request start, subtracting the complete exchange latency, and intersects successive readbacks. A public receipt value cannot construct this process-local proof. Callers must retain the actual controller session and reconcile expiry; closing a channel does not prove process or native cleanup.

The local actual contract runs the real Rust executable in a disposable private network namespace. It verifies static, layered, DNS and staged-set policies, rejects a real weakened policy with unchanged owner/revision/live element, observes renewal refusal after kernel expiry, and confirms timeout clipping plus dispatch refusal at the original lifetime. It also confirms that this partial floor setup cannot issue a full protected receipt. Container removal and exact physical-ID absence collect the private namespace.

Supported-host runc and gVisor gates separately exercise a fully protected running supervisor: actual policy application, duplicate refusal, held-session renewal, tightening, expired-lease refusal and fresh quarantine. They independently verify the final complete deny table and unchanged floors, runtime ID/PID/start time, absence of user executions and no Ready publication. The existing bootstrap, DNS replacement/collision and packet gates remain mandatory. Local private-namespace success does not replace those full hosted gates.
