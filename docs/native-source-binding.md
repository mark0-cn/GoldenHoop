# Native source binding from provider addresses

The production Docker driver can bind independently checked endpoint addresses to the sole actual host bridge port through the trusted Rust controller. This extends guarded bootstrap with an immutable source floor. It does not publish workload Ready or grant a packet lease. DNS, destination protection, live worker orchestration and lease/policy recovery remain required; NetworkPolicy and SecretInjection stay unadvertised under the full M0-M6 objective.

`EndpointAddresses` carries only the trusted provider MAC, IPv4 and optional IPv6 tuple. It rejects a caller-supplied port or interface index. The driver first repeats its complete container/network endpoint inspection, validates the actual enforcement session's frozen native identity and dispatch expiry, and requires confirmed quarantine plus Ethernet protection with no existing source binding. It then calls the new private `bind_runtime_source` operation. The historical trusted `bind_source` command remains available for existing mechanism contracts.

The controller checks its original bridge index, kind and ownership alias. It reads at most two entries from that bridge's actual `brif` directory and requires exactly one. Linux links a `brif` entry to the interface's `brport` directory, which has no interface `ifindex` file. The implementation validates the name, requires a symlink and checks its canonical target against the global interface's `brport`. It reads the index from `/sys/class/net/<port>/ifindex`, checks the original master index and repeats identity reads. The private filesystem-root parameter exists only for model tests; production uses literal `/sys/class/net`.

The controller combines the observed host port with the provider addresses and calls the existing source installer under known quarantine. After the actual nftables acknowledgement, it reads the sole port again, checks the source descriptor and complete rule semantics, and rechecks the actual gateway MAC/addresses. Only a healthy matching native/guard readback produces a typed `SourceBindingReceipt` containing the original allocation, source scope, current revision and observation time. A failed post-write confirmation marks the manager uncertain and disables renewal. Reading a native interface alone is not installation success.

The driver validates the receipt's complete allocation, revision, provider addresses and gateways, repeats both endpoint views, and requires the controller's source digest and revision to match. An error or inconsistency after dispatch fences that private channel. EOF does not attest process exit or cleanup. A duplicate request is refused before dispatch when the source floor is already present. The private bootstrap contract persists Starting before supervisor launch and keeps that state after source installation.

On a supported host, the actual bootstrap contract independently inspects the target bridge/port symlink, indices, gateway addresses and owned kernel source table using the pinned disposable fixture. It checks the source owner/version markers, captures the source table and then requires actual production-worker collection. The existing packet source gates continue to test their complete anti-spoofing/ARP/neighbor cases. The new full source-binding composition requires separate runc and gVisor hosted acceptance. The local Desktop kernel remains limited to the explicit unsupported-bridge refusal gate.
