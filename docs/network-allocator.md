# Durable network allocation identity

Status: the schema-8 store retains private allocator/native identities and adds a [durable controller dispatch journal](controller-journal.md). The owned Docker bridge provider, Rust native alias binder and trusted controller process provider are implemented. File-backed metadata tests use synthetic provider/kernel observations; separate backend contracts exercise actual Docker and native kernel observations. Production worker/workload integration, policy revision recovery and isolated-child network provisioning remain incomplete. No NetworkPolicy capability is advertised by these components.

The [trusted controller provider](network-controller.md) adds pinned Docker process creation, checked host placement, private Rust stdio and process collection. Its dispatch journal now preserves process epochs and create/start fences; production worker composition remains incomplete.

The trusted worker must reserve a generation before any Docker network creation. The journal derives its exact network name and bridge name from that generation, binds it to the installation, sandbox and profile, and records a provisioning token before external I/O. A crash retains that intent and token. Recovery must inspect the planned owned resource; retrying network creation from an absent response is refused. Repeating an identical reservation is idempotent; changing generation or identity is not.

Only a fresh pending root sandbox can reserve this initial allocator record. A running workload cannot acquire it retroactively. Isolated children return UnsupportedCapability until their allocator and ancestor accounting are integrated; the complete M0-M6 objective still requires that integration. Existing default-deny production runtime behavior is unchanged.

`NetworkNativeBinding` records the actual Docker network ID and native allocation (installation, sandbox, generation, bridge and interface index) while the journal remains Provisioning. The trusted worker must persist it before writing any bridge alias or packet table. Exact replay changes no revision, creates no source/DNS binding and acknowledges no enforcement or lease. Fresh writes require a live pending/starting root without a dispatched runtime handle; cancellation, expiry, collected generations and foreign/live-colliding identities refuse. A changed interface index cannot replace the recorded one, including after process restart.

`NetworkBinding` then freezes the endpoint source scope and destination/DNS definition against that exact native checkpoint. New complete bindings without the native checkpoint refuse. Initial complete-binding writes also require a still-live provisioning sandbox; an identical stored binding remains a read-only replay. Schema-6 complete bindings already contain their physical identity, so schema-7 migration derives it on read without rewriting current payloads or append-only history bytes.

`NetworkBinding` freezes the actual Docker network ID, native bridge/index, endpoint source scope, and destination/DNS definition. The allocator must first verify provider ownership labels, actual bridge membership, link identities and addresses. The store validates canonical data and cross-field identity, rejects foreign installation/sandbox/generation, and prevents live bridge/index or network-ID collisions. Exact binding replay preserves its revision. A changed binding cannot replace it. A fingerprint identifies data; it does not attest enforcement. Bound means resource identity is recorded, and grants no packet permission or controller lease.

Collection has its own persisted token and invalidates the creation token. Late binding cannot win after collection intent. Confirmation requires a fresh observation of all endpoint, provider-network, native-bridge and owned-filter absence, plus evidence that outstanding provisioning has finished or been fenced so it cannot materialize the generation later. A lookup failure or stream EOF does not establish those conditions. Missing/false conditions, stale/future observations and wrong tokens refuse confirmation. Token checks and state/history writes commit atomically under BEGIN IMMEDIATE transactions.

A sandbox cannot publish Complete cleanup while its network journal remains uncollected. A late owned resource observation reopens collection as Unknown, retains the known resource identity, clears obsolete operation tokens and restores the root sandbox's quota charge and reconciliation work. Prior terminal business operations remain immutable. Every journal mutation appends a complete revision snapshot, so a previous absence observation remains inspectable after residue is discovered. History reads have bounded limits and explicit cursors.

The store accepts observations from the trusted worker; it does not perform Docker or kernel lookups. Private Rust methods are not public API endpoints. Runtime enforcement remains dependent on the actual source/destination contracts, a journal-bound provider/controller transport, installation before workload publication, known quarantine on controller recovery, policy/lease/deadline handling and actual owned collection. Credentials, scoped keys and redacted audit remain separate M3 requirements.

## Owned Docker bridge provider

`NetworkIdentity` shares the versioned installation/sandbox/generation/profile identity, exact planned network/bridge names and derived ULA subnet between the journal and provider. Its unkeyed digest identifies data and is not an authentication secret. `NetworkPlan` additionally binds the committed provisioning token and initial deadline. The provider requires a Linux x86_64 daemon with [Docker Engine API 1.53](https://docs.docker.com/reference/api/engine/version/v1.53/) or newer through the existing local socket/named-pipe transport.

Creation is a distinct fresh-dispatch operation. A successful inventory must first show that the planned name is absent; a failed request or inspection never authorizes an automatic retry. Recovery only looks up that name, rejects multiple/foreign matches, then fully inspects the actual canonical ID. Required labels, local bridge type, flags, exact options and dual-stack IPAM must match the plan. IPv4 uses a native RFC1918 pool with a usable gateway; IPv6 uses the planned /64. ICC is disabled, both gateway modes use NAT and default host publishing binds loopback. These provider options do not replace the immutable packet/source/Ethernet contracts.

Full network inspection must contain an actual endpoint map; the [network-list response](https://docs.docker.com/reference/api/engine/version/v1.53/) cannot establish that no container is attached. Collection refuses any endpoint, validates a supplied canonical ID, removes only the owned empty network and requires successful name/ID inventories afterward. A 404 or failed inspection is not absence. The result proves provider absence only; native bridge and owned nft table absence remain independent requirements before journal completion.

The private Rust `network_allocation` example first probes the existing runc development driver, then reserves/dispatches a root record before creating an empty bridge. Its controlled exit occurs after the actual create call returns and before a binding result is persisted; it does not claim an injected TCP outage. The outer contract discards creator output and reads the file database, independently observes network identity/creation time/native index before and after recovery, checks foreign owner/token/profile/deadline/ID and duplicate/expired refusal, and attaches a trusted zero-capability sleeping diagnostic to prove live collection is refused. It publishes no user workload or policy permission.

After removing that diagnostic and the provider network, an allocation-scoped trusted NET_ADMIN helper reads the actual host namespace. Only settled provisioning plus fresh complete provider/kernel absence can finish the journal. The harness validates ownership before cleanup, checks final inventories and removes its temporary database and disposable fixture. Interrupted or uncertain creation retains recovery state instead of treating EOF as cleanup.

## Private controller transport

The host packet manager and Rust worker transport share `goldenhoop_egress::controller::{Envelope, Request}`. The wire remains bounded JSON lines with a numeric request ID and an operation object. Empty install/inspect commands use empty struct variants so Serde rejects unexpected fields; the original unit variants accepted them despite the enum-level deny-unknown setting. Existing DNS defaults and valid command encodings are preserved.

`controller::Client` permits one in-flight call, bounds request serialization and reply reads to 256 KiB, and correlates each complete response with its request. Local oversize requests and deadlines already expired before dispatch write nothing. Before its first I/O await, the client marks the channel uncertain. Partial writes, a dropped polled future, timeout, EOF, malformed/oversized replies, extra buffered frames or mismatched IDs leave that fence in place. Further calls, including renewals, are refused; the client never replays a possibly applied command. Recovery needs the durable owned identity and an independently opened controller channel.

A complete matching error reply is a controller observation and can follow a partial external write. A result reply likewise needs journal/revision/binding validation before the worker can treat it as enforcement evidence. This transport provides no collection attestation. The trusted process provider and durable dispatch journal now compose this transport. Initial quarantine/binding, renewal scheduling, recovery, source/DNS/workload composition and capability publication remain part of M3 integration.

Portable tests use actual bounded asynchronous duplex I/O for framing, correlation, cancellation after partial/full writes, withheld replies and local refusal. A Linux-only test launches the actual egress executable through private pipes with a cleared environment, observes refusal of inspect/renew before any allocation is opened, then closes the channel and waits for a successful process exit. It creates no allocation or packet state. Actual provider/kernel contracts remain separate gates.

## Native bridge ownership binding

The private `bind_native` command accepts a complete allocation identity, provisioning token and immutable dispatch expiry before a manager is opened. The trusted caller must first validate the matching provider and persist the native checkpoint; the command itself does not authenticate a database. Identity validation requires the exact installation/sandbox/generation, derived bridge name, positive native index, non-nil token and a live deadline. It requires the same NET_ADMIN-only, no-new-privileges authority as the packet manager.

The Linux implementation takes the physical bridge lock and the existing allocation lock, reads actual sysfs index/kind/alias and refuses every foreign alias. Direct Rust route netlink changes only the indexed interface's alias. A bounded kernel acknowledgement must match the request before the implementation reads the identity and alias again and rechecks expiry. Identical replay observes the existing alias without rewriting it. No external `ip` process is used by production code. This is an ownership observation, not a source, DNS, packet, journal or lease attestation.

An open manager holds the allocation lock and refuses alias binding on its own channel; another binder also refuses while that manager is alive. Cancelling the asynchronous bind does not cancel its blocking kernel exchange. Recovery and collection must settle the controller process before treating external writes as finished. Unknown acknowledgement or expiry after a write never grants enforcement success.

The [13-group actual local contract](evidence/m3-network-native-alias-provider-runc-windows-docker.json) includes all eight provider/checkpoint groups, then verifies missing/extra capability refusal, stale/foreign identity refusal, unchanged foreign and newline aliases, a native Rust write with independent `ip` readback, replay, same-process and separate-controller exclusion, and confirmed controller exit. It starts from the actual persisted native checkpoint after process exit 76. No packet tables are created, and the provider, bridge, audit/controller containers and private database are confirmed collected. `tests/controller_provider_contract.py` composes this native contract with durable controller dispatch and is the host prerequisite CI gate; composed runc/gVisor packet gates remain separate and mandatory.
