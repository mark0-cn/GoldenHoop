# Automatic native discovery and pre-native collection

The Rust control layer can discover an actual owned Docker bridge without a caller-supplied interface index. A separate short-lived trusted process reads native identity; it is positively collected before the store accepts a native checkpoint. The production worker can also collect an interrupted allocation that has no native checkpoint. These operations grant no workload execution, packet policy, lease or Ready state. Full live-worker policy and lease orchestration remains required under M3; NetworkPolicy and SecretInjection remain unadvertised.

Schema 10 adds typed `ProbePlan` records to the existing durable host-process journal. `HostProcessPlan` is an untagged union of the original `ControllerPlan` and a probe plan. Historical native plan serialization, payloads and append-only event bytes remain unchanged. Native enforcement and collection still require a complete allocation with a positive interface index. A probe cannot be cast into a native controller, and an unknown index is never represented by zero.

`Discover` freezes installation, sandbox, allocation and process generations, profile, the positively observed provider network ID, original provisioning token and absolute expiry, and the administrator's immutable image ID. Its name includes both generations. Creation intent, physical ID and start intent use the same durable dispatch fences as controllers. A dispatched create or start is never replayed. A fresh process epoch requires all previous processes to be collected; the sandbox has a bounded process history.

The Docker provider admits only the pinned trusted host-controller image with its checked defaults. The fixed command is `goldenhoop-egress --probe-native <plan>`. A discovery process runs as UID 1000 with zero capabilities, no-new-privileges, host networking, a read-only root filesystem, private IPC/cgroup namespaces, no mounts, no stdin or control server, bounded resources and no restart or auto-removal. Its metadata-only stdout uses bounded local logs. Full inspection verifies actual placement, ownership, image, complete arguments, streams, capabilities and log bounds before use. Image markers are checked configuration, not signatures.

The Linux executable independently checks actual credentials and reads only the derived bridge under `/sys/class/net`, its positive index, bridge kind, alias and actual gateway addresses. It repeats identity reads around gateway observation. A foreign alias, missing gateway, stale identity or malformed plan refuses. The bounded receipt is bound to the complete plan hash. The control layer requires an actual successful process exit, a single valid stdout receipt, unchanged process identity and positive process collection. It then rechecks the same empty provider network and both gateways before persisting the checkpoint. This checkpoint remains historical provenance: native alias binding and subsequent guard installation must inspect the actual native identity again.

For terminal work without a native checkpoint, the worker first settles every original process. A lost create acknowledgement can be recovered only by positively observing its exact owned object. A dispatched creator with neither a recorded nor observed physical ID remains unknown. No empty inventory can turn that uncertainty into completed cleanup.

The worker recovers the original provisioning token from immutable history, checks the exact empty owned provider and freezes any known network ID in a new `ObserveAbsence` plan before removal. An allocation that was reserved but never dispatched instead requires exact reserved-name absence and has no invented provider ID or token. Conflicting physical identities or native-controller history without its native checkpoint refuse.

`ObserveAbsence` keeps the original expiry, including an already expired deadline, and adds a separate immutable dispatch window of at most 60 seconds. Its trusted executable runs with NET_ADMIN solely to read the complete nft table inventory; this capability places the helper in the trusted computing base. The command changes no alias or rule. It checks the derived bridge twice and all four generation-specific table names, returning only their absence booleans and observation time. Unrelated native table identifiers are omitted. A remaining owned table blocks completion and is not deleted by this read-only path.

After this process is positively collected and provider absence is rechecked, the worker can commit fresh native absence while `network.native` remains absent. The existing observation-age, process-settlement and sandbox cleanup requirements still apply. A process exit, provider removal or absence receipt alone is insufficient.

The actual local contracts cover reservation cancellation, exit 83 after acknowledged creation before ID checkpoint, exit 84 after start acknowledgement before the running checkpoint, and an actual generation-specific marker table that blocks cleanup until the test removes its exact owned marker. The private guarded-bootstrap suite now invokes automatic discovery; independent host observations are comparison evidence, not interface-index inputs. Full bootstrap and DNS replacement/collision gates remain mandatory on supported runc and gVisor CI hosts.

Portable tests use an unmodified actual discovery-container capture to reject added privileges, stdin, foreign arguments, mounts and unbounded logs. File-backed migration tests preserve schema-9 enforcement and collection payload/event bytes and original dispatch tokens. These tests establish admission and durable-state behavior; the separate real-backend records establish actual process and kernel observations.
