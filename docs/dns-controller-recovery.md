# DNS recovery in a replacement controller

The Rust driver can restore the exact owned DNS sockets in a fresh enforcement controller under quarantine. The previous controller must be positively settled and collected through its journal before the store authorizes a new epoch. Original installation, sandbox, allocation generation, bridge index, provisioning token and absolute expiry remain unchanged. Only the controller process identity changes. This restores protected provisioning, not a policy lease, workload Ready or execution permission.

The new private `recover_dns` command carries an expected kernel revision, fixed administrator-owned upstream, and the original source/destination scopes. Its expiry comes from the original native dispatch frozen by `bind_native`; the command cannot extend the lifetime or authorize alternate ports. The manager accepts it only immediately after attaching a new manager: no local revision, configured DNS, active lease or running frontend may exist. It also requires the actual Ethernet, source and destination guards already present and healthy. The abstract allocation lock prevents another active manager from attaching concurrently.

The manager compares both scopes against the actual immutable descriptors, reconstructs the exact original DNS tuples, and verifies the native source port and gateways. It captures the original remaining lifetime as a monotonic deadline before asynchronous observations. Invalid families, gateways, canonicalization, expired deadlines and recursive upstreams refuse. Configuration does not recreate or weaken the immutable floors.

Recovery then replaces the previous inet policy with complete quarantine at the next revision, including explicit protection of every original DNS tuple. It verifies the full deny table and immutable/native readbacks before binding sockets. Only then does it rebind paired TCP/UDP sockets at those exact addresses and ports, repeat the native checks and hand the sockets to the bounded frontend. The DNS model, source credits and lease book start empty. No prior policy or live lease is resumed.

A port collision or failed readback leaves quarantine in place and marks the manager uncertain. The driver fences the channel on failure, inconsistency or cancellation. It never chooses a replacement port. A retry needs independent process settlement and a newly authorized epoch. EOF is neither successful recovery nor completed cleanup.

`DockerDriver::recover_quarantined_network` first checks the held fresh session's frozen native plan, the previous protected receipt and both Docker endpoint views. It refuses an already-open session before a native mutation, then binds the original native context, attaches the manager and compares the actual guard digests. After recovery it checks the original source, destinations, exact listeners, expiry and fresh observation times, repeats provider inspection, and requires a second fresh protected receipt. The caller must retain the session for later policy/lease reconciliation; the returned value alone cannot authorize Ready.

The private allocation contract accepts `controller-resume-binding-json` only for bound-runtime controller creation or resume. It compares the input to the existing SQLite network binding, original sandbox expiry and Starting state. The store still requires all old controller epochs collected before reserving another, and records create/start intent and actual physical identity. Resume never starts or recreates the workload runtime.

The real `dns_recovery_contract.py` runs separately on runc and gVisor. After full bootstrap it collects the actual exited controller, keeps the bridge and all floors, and refuses a changed DNS port before reserving another controller. It then starts a new epoch and requires exact dual-stack DNS recovery with unchanged source/destination table identities and expiry. It independently verifies the actual inet deny table with the Rust verifier, checks unchanged workload ID/PID/start time and an empty execution table, then collects that replacement. A zero-capability owned helper occupies an original high TCP DNS port. A further fresh epoch must fail at that exact bind, settle its process and retain a complete next-revision quarantine. The production worker finally collects the runtime, all controller epochs, bridge and table scopes. No upstream query or user execution is allowed.

Portable tests cover the original listener families/addresses, canonical scope and strict recovery wire authority. Actual stdio tests require InvalidState before manager attachment and Forbidden in collection-only mode. These checks are separate from successful composed recovery on a supported host. The local Desktop kernel lacks bridge-family filtering; positive recovery and occupied-port acceptance require the hosted runc/gVisor gates and remain unverified until those results complete.

The first [replacement workflow](evidence/m3-network-native-ci-45634703633-archive.json) failed on both runtimes before starting a replacement controller. The changed-port request returned the expected immutable-state Conflict, while the test incorrectly required InvalidRequest. Both exact error frames and absence of a create intent are preserved. The predicate now requires that specific Conflict and message, with no create intent; [read-only replay](evidence/m3-network-dns-recovery-refusal-replay-windows.json) passes against both actual failed records. All 11 records have Complete cleanup. Fresh recovery/collision execution remains unverified, and later packet steps in that failed workflow were skipped.

The production worker still terminates and collects owned-network journals. [Automatic native discovery and pre-native collection](native-probes.md) now have separate process and recovery contracts. Held policy/lease sessions, live-worker recovery/Ready orchestration, credential isolation and the remaining M3-M6 requirements remain required. NetworkPolicy and SecretInjection stay unadvertised.
