# Production worker owned-network recovery

The production Rust worker can collect a persisted owned network and controller after sandbox expiry. This is terminal recovery. Live policy startup, endpoint/source/DNS/destination composition, lease scheduling and capability publication remain required under M3; M4-M6 remain required. NetworkPolicy and SecretInjection are unadvertised.

Schema 10 also supports [terminal collection before a native checkpoint](native-probes.md). The worker settles original probe processes, freezes known provider identity before removal and runs a separate read-only bridge/table absence probe. Unknown dispatched creation remains unknown. Native absence is confirmed without inventing an interface index; a remaining table blocks cleanup rather than being deleted by this path. The existing positive-native collector below remains unchanged in purpose.

An administrator supplies a locally present immutable host controller image with `goldenhoopd worker --egress-controller-image sha256:...` or `GOLDENHOOP_EGRESS_CONTROLLER_IMAGE`. The worker validates the pin. Existing process collection uses each journal's original frozen image. A missing configuration or unavailable required image leaves cleanup pending with an error.

An owned-network journal fences the existing none-network runtime path: reconciliation requests termination before any normal workload creation. Stopping removes runtime work, closes execution/context work and waits for child collection. It then begins network collection, atomically fencing old controller dispatch. The worker looks up and collects the exact owned controller identity. A positive physical ID can recover a lost creation acknowledgement; a dispatched creation without a positive ID remains unknown even when lookup is empty. A reservation never dispatched can be settled without an ID.

The worker recovers the original provisioning token from immutable history, validates the native checkpoint and removes only the matching empty provider network. It does not infer native identity from a name or an empty inventory. A missing native checkpoint remains pending. Bridge removal precedes filter removal, so a live network cannot lose its deny boundary through this recovery path.

Schema 9 freezes a new collection-purpose controller epoch with the original native allocation, original sandbox expiry and an independent 60-second dispatch/call deadline. Enforcement and collection each have a separate 128-epoch budget. Old normal plans omit the new fields, preserving existing serialized labels. Schema 8 payload/event bytes survive upgrade unchanged; old binaries refuse schema 9 rather than interpreting the new purpose as enforcement.

The provider starts a collection epoch with the fixed `--collection-only` argument. Both the Rust session and actual executable reject every command except Open, Inspect and Remove. It cannot install/renew rules, change an alias or enable DNS, source, Ethernet or destination permissions. The dispatch window does not extend the workload deadline and does not claim an independent process auto-exit timer.

The existing manager reopens and validates owned tables even after the bridge has disappeared. Remove checks bridge absence, validates the expected owned revision and all guard descriptors, deletes scoped owned tables and reads back absence. Only collection mode returns a typed receipt containing the original allocation, bridge/table absence and its observation time. The worker checks the receipt, closes and independently collects the process, rechecks provider absence and commits the network absence using that original observation time. Controller and network collection must finish before sandbox CleanupComplete. A channel close, successful process exit or provider absence alone cannot authorize that state.

The [seven-group actual local contract](evidence/m3-network-native-worker-recovery-runc-windows-docker.json) starts from an actual file-database network/native checkpoint, installs a revision-zero deny table and observes producer exit 0 while the rule remains. It waits for real wall-clock sandbox expiry before starting the production worker. The worker collects both process epochs, bridge and table without changing user expiry. Independent host readback checks all four table scopes, and bounded Docker creation events confirm only a collection controller was created for the target sandbox. Registration evidence contains profiles only and verifies NetworkPolicy/SecretInjection remain absent. It is recovery after a private producer exits, not an injected crash of an already-running production worker.

The [controlled harness-failure record](evidence/m3-network-native-worker-recovery-controlled-failure-cleanup-windows-docker.json) intentionally remains Failed. It interrupts immediately after the owned quarantine is observed. Failure cleanup verifies ownership, removes the empty bridge, invokes the actual collection-only manager against revision zero, checks the typed receipt and independently verifies absence before deleting private state. Its cleanup is Complete. This proves scoped harness failure cleanup; it is not an additional production worker pass.

Strict [Windows gates](evidence/m3-network-native-worker-recovery-validation-windows.json) pass 172 tests; strict [Linux gates](evidence/m3-network-native-worker-recovery-linux-build.json) pass 190 tests and both musl builds. Linux includes an actual executable/stdio test refusing enforcement commands in collection mode. Store tests use synthetic shifted dates for dispatch invariants and schema migration; real expiry is established separately by the contract above. The existing [23-group provider regression](evidence/m3-network-native-worker-recovery-provider-runc-windows-docker.json) also passes. Hosted acceptance of this new production integration is a separate release gate.

The [21-group actual API/client regression](evidence/m3-network-native-worker-recovery-api-runc-windows-docker.json) passes with Complete cleanup. [Final scoped cleanup](evidence/m3-network-native-worker-recovery-cleanup-windows.json) verifies 12 installation-scoped container/network/volume inventories empty across the four attempts, all five controller IDs absent, three native bridges and 12 table scopes absent, private directories removed and both disposable images and the superseded agent image collected. Source, useful caches/tools, raw evidence and the exact current agent are retained. The [initial final-audit attempt](evidence/m3-network-native-worker-recovery-cleanup-initial-windows.json) failed only because its absence-message assertion expected capitalized Docker CLI text; all 12 inventories were already empty. The corrected audit accepts case variations while requiring the actual unsuccessful inspection and complete native/provider readbacks.
