`ProtectedDestinations` takes a `DestinationScope` from trusted provisioning: kernel-observed host addresses, administrator-owned control-service addresses and explicit private-subnet exceptions. Virtual control-service IPs must be supplied even when they are absent from host interfaces. A supplied scope is data, not proof of a current kernel observation. User network policy must never populate these administrator fields.

The model bounds input before compilation: 128 host addresses, 64 control addresses and 32 private exceptions, with at most 64 bytes per exception. Exceptions must be canonical, host-bit-free subnets contained in the supported private classes. Public/overbroad subnets, mixed-family mapped forms, unknown fields and command text are refused. Sorted, deduplicated scope data has a version-bound SHA256; that digest is identity data, not authorization or proof of enforcement.

| Class | Meaning |
| --- | --- |
| `Protected` | A pinned host/control address or a built-in hard restriction; private exceptions cannot exempt it |
| `PrivateDenied` | A supported private address without an administrator exception |
| `PrivateException` | Exempt from this floor's private restriction; still requires effective user/ancestor policy and actual installation |
| `Other` | Outside these lists; no public-routability or permission claim |

Private classes include [RFC 1918](https://datatracker.ietf.org/doc/html/rfc1918) IPv4 ranges, [RFC 6598](https://www.rfc-editor.org/info/rfc6598/) shared address space and [RFC 4193](https://www.rfc-editor.org/info/rfc4193/) unique-local IPv6. Hard restrictions cover unspecified/loopback, link-local, multicast/reserved, mapped/compatible IPv6 and deprecated site-local address forms. Classification preserves the native family rather than converting an IPv6 DNS record into an IPv4 private exception.

Known special endpoints include AWS's [IPv4/IPv6 IMDS addresses](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/configuring-IMDS-new-instances.html), Alibaba's [100.100.100.200 metadata service](https://www.alibabacloud.com/help/en/eci/user-guide/obtain-the-metadata-from-a-container-2) and Azure's [168.63.129.16 platform endpoint](https://learn.microsoft.com/en-us/azure/virtual-network/what-is-ip-address-168-63-129-16). These remain protected even inside a broader private exception. The list does not discover every provider-specific service; deployment-owned control endpoints remain necessary.

The standard [RFC 6052](https://www.rfc-editor.org/info/rfc6052/) and [RFC 8215](https://www.rfc-editor.org/info/rfc8215/) translation prefixes are conservatively protected until their translation path has its own enforcement contract. Custom translation, tunnelling and an allowed remote service's own forwarding behavior are not inferred from this address classifier. Production network profiles must account for their actual topology before claiming a boundary.

Four portable model regression groups check independent native boundary/metadata/translation vectors, private exceptions that cannot exempt host/control/metadata addresses, strict parsing and quotas, and deterministic scope identity. Five packet-plan regression groups use complete unmodified actual kernel tables: they check ownership, exact ordered rules and all hooks; changing counters/handles preserves identity, while missing/reordered rules, dormant tables, foreign owners, altered ports/prefixes/verdicts and weakened/moved infrastructure exemptions refuse confirmation. The local-route rule cannot be omitted, restricted to the ingress interface, or moved after a private exception. A historical v1 descriptor is recognized for owned collection only and cannot confirm v2 protection. These tests complement actual packet acceptance.

## Private packet and DNS integration

Private `protect_destinations` binds once after a known quarantine revision. The manager obtains initial host addresses from bounded `getifaddrs` observations and derives DNS exemptions from its already-bound listeners. The caller supplies only administrator private exceptions and control addresses. Invalid input leaves the known configuration unchanged; an existing floor cannot be replaced or weakened. The initial host/control pins remain immutable even after an address disappears. Later policy and lease confirmations require the exact immutable table and owned bridge/DNS infrastructure, while unrelated host-address additions do not change the allocation's digest or revision. This private interface is not an API exposed to workloads.

The separate `gh_d_<generation>` inet table retains allocation ownership, version, a bounded complete descriptor and its digest. Three filter hooks run at priority -210: prerouting checks original destinations before conntrack/NAT, and input/forward check final destinations after prerouting translation. Each checks the allocation's bridge name and native interface index. Other ingress interfaces return without a new permission. Version 2 checks `fib daddr type local` after exact DNS infrastructure and before static restrictions/private exceptions. This consults current kernel local routes for both native address families, including addresses assigned to other interfaces, rather than relying on an initial host list. The [nftables FIB expression](https://netfilter.org/projects/nftables/manpage.html) documents destination route-type lookup; adding `iif` would constrain the lookup and is refused by readback. Static protected addresses precede private exceptions, which precede private denial. All successful floor paths return to later filters; the floor emits no application accept verdict or established-connection bypass.

The original owned gateway's TCP/UDP port 53 can pass prerouting for its protected DNS redirect. Only the exact bound gateway/high-port TCP/UDP tuples can pass final host checks; other host application ports remain denied. Direct IPv6 NS/NA with hop limit 255 and code zero has a link-neighbor path in prerouting/input. The mandatory source floor validates its sender, target, message length and options, and the Ethernet floor still forbids same-bridge forwarding. The component-only development gate omits those unsupported Desktop bridge mechanisms explicitly and never substitutes for the composed gate.

DNS checks every raw A/AAAA candidate against both the immutable scope and a fresh bounded native host-address observation before source-book staging or timed-set installation. Protected/private-denied and current host candidates receive an address-free refusal. A private exception still requires effective policy and a confirmed grant. Before committing the source credit and returning an address, the installer rechecks current host addresses, revision, physical scope and all required immutable guards. Empty, failed or oversized native observations cannot acknowledge a grant. Per-packet local-route enforcement remains in the kernel across observation races and later address changes. The installer does not extend the global controller lease. Binding or changing DNS infrastructure after the floor is refused.

Restart reads the complete owned descriptor and reconstructs exact expected table semantics; a partial, extra, dormant or altered rule graph cannot confirm a guard. Collection validates ownership and descriptor even when rule health is unknown, requires actual bridge absence, atomically removes all owned packet tables and confirms actual absence. Durable desired-state storage and frontend restoration are composed by the [worker-held session path](worker-network-policy.md); this descriptor/readback component alone grants no live worker authority.
