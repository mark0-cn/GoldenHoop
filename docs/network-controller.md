# Trusted host controller provider

Status: the Rust Docker provider implements pinned-image controller creation, actual configuration inspection, private stdio startup, successful process-exit observation and owned process collection. The [dispatch journal](controller-journal.md) persists process epochs, purposes and dispatch fences. The production worker integrates [terminal owned-network recovery](worker-network-recovery.md), including collection after actual sandbox expiry. The Docker driver adds [guarded creation/startup](guarded-bootstrap.md) and [native source-binding entry points](native-source-binding.md); local kernel-refusal acceptance does not establish successful composed source installation. Live worker startup/source/DNS/destination composition, policy/lease recovery, hierarchy integration and capability publication remain required under M0-M6. Neither NetworkPolicy nor SecretInjection is advertised.

The administrator supplies a locally present immutable `sha256:` image ID. The provider uses only the local Docker socket or named pipe, requires Linux x86_64 and API 1.53 or newer, and never resolves a tag, pulls an image or selects another runtime. The image must have the trusted controller entrypoint, the host-netfilter marker and only the expected PATH environment; declared volumes, ports, commands, health checks and build hooks are refused. The marker is checked configuration, not an image signature or a source of administrator authorization.

The caller must persist the native allocation checkpoint and complete controller plan, validate the actual owned network, and serialize this sandbox's reconciliation before external writes. `ControllerPlan` freezes native identity, provisioning token, absolute expiry, image ID and a separate process UUID. New physical names include both network and process generations; exact labels retain the full plan. The provider itself neither authenticates a store nor attests the native checkpoint. A fresh durable dispatch is mandatory for create/start; a missing response never authorizes replay. Historical plans without a process UUID permit inspection/collection only.

The controller runs as `0:0` with host networking and the explicit trusted runc runtime, read-only rootfs, all capabilities dropped except NET_ADMIN, no-new-privileges, private PID/IPC/cgroup namespaces, no workload or host mounts, bounded memory/CPU/tasks, disabled logs and no automatic restart/removal. Workload runtime selection remains the responsibility of its separate driver. Complete Docker inspection checks the physical ID, immutable image, plan labels, entrypoint, environment, streams, mounts, namespace placement and resource/privilege controls before use. Portable inspection tests use an unmodified actual capture and altered ownership/privilege/placement observations; they perform no daemon I/O.

`lookup` uses a positive all-state name inventory and full inspection. It only observes; it does not create or start anything. `start_created` accepts an exact positively observed ID in Created state, attaches before starting, then requires an actual Running observation. Each create/start attempt is locally fenced before its write, including cancellation and uncertain responses. Running and exited instances are never restart targets. After a worker restart, its durable dispatch history must supply the corresponding fence; the provider's in-memory set is not a replacement for that history.

The private channel uses the shared bounded, correlated Rust controller client. Open/native-bind requests must match its frozen allocation/plan. Each call is bounded by both the caller's deadline and the immutable sandbox expiry. Malformed frames, EOF, uncertain writes, timeout and cancellation preserve the client's existing uncertainty rules and never replay a command or renew a lease. The Docker attach decoder receives output only from the pinned trusted binary; decoded chunks and control frames remain bounded before a reply is accepted.

`ControllerSession::close` drops the channel and requires a fresh Exited observation with exit code zero and no running/paused/restarting/dead state. EOF alone does not prove this. Explicit `collect` inspects ownership before forced process removal, then requires empty name and ID inventories and a missing exact-ID inspection. It accepts expired identity for collection, while new dispatch and calls require live expiry. A previously positively observed ID is mandatory: unknown creation with no observed object cannot be converted into absence by supplying an empty name inventory. Failed/cancelled writes need independent recovery and process settlement.

Process collection does not establish native bridge, packet table, endpoint, DNS or journal collection. An uncertain channel must be fenced and the controller settled before any native cleanup is declared complete. Full M3 composition must still install and confirm all required guards before untrusted execution and renew them only from trusted, live reconciliation.

The [protected quarantine binding](protected-network-binding.md) now freezes the original native dispatch in the enforcement process, configures DNS from its absolute expiry and returns a typed source/DNS/destination readback while no live lease exists. Collection-only processes reject these commands. This is a guarded provisioning step; held policy/lease sessions and their restart recovery remain required for live worker publication.

The subsequent [DNS recovery path](dns-controller-recovery.md) lets a fresh controller replace the old inet policy with verified quarantine, bind the exact original sockets and return fresh protected readbacks. Its source/destination descriptors, native identity and absolute expiry must match the original binding. An occupied port refuses and fences the session. This does not recover a policy/lease or publish Ready; the dedicated supported-host replacement/collision gates are separate acceptance evidence.

The [effective-policy path](effective-policy.md) adds complete policy and finite kernel-lease readbacks to application, renewal and DNS activation. The Docker driver holds a process-local monotonic lease across policy application, tightening and renewal. It preserves the original binding and expiry and fences uncertain mutations. Live worker ownership, scheduling and Ready publication remain required.

The private allocation example uses the [durable journal](controller-journal.md), now at schema 10. Its [automatic native probe](native-probes.md) supplies the actual positive bridge index before native controller reservation. Controlled exits after acknowledged creation and after committed start intent verify independent recovery fences. Recovery reads the pinned image and physical identity from the file database, without resolving a new image tag or replaying start. The worker still needs to compose these records with packet enforcement and workload publication.

The [previous 20-group actual contract](evidence/m3-network-native-controller-provider-runc-windows-docker.json) verifies the full provider/native foundation and Rust controller lifecycle, including an actual alias write through the Docker stdio transport. Its 117 source fingerprints belong to the original provider increment and are not current-source acceptance. The [21-group API/client regression](evidence/m3-network-native-controller-api-runc-windows-docker.json) confirms existing production behavior. [Windows gates](evidence/m3-network-native-controller-validation-windows.json) pass 161 tests; [Linux gates](evidence/m3-network-native-controller-linux-build.json) pass 178 tests and both musl builds, with strict format/clippy in both environments. [Final cleanup](evidence/m3-network-native-controller-cleanup-windows.json) rechecks both actual provider attempts and the API installation, native absence and disposable/superseded image collection.

The [initial actual capture](evidence/m3-network-native-controller-provider-initial-runc-windows-docker.json) passed and supplied the immutable inspection fixture; it precedes the pure-inspection extraction and stronger alias-write case and is not current-source acceptance. The [initial Windows](evidence/m3-network-native-controller-validation-initial-windows.json) and [initial Linux](evidence/m3-network-native-controller-linux-initial-build.json) full checks remain failed: the first portable fixture constructed a Docker client and depended on a host socket. Extracting pure request/inspection functions removes that dependency without skipping configuration checks. The final gates and actual contract above cover the corrected code.
